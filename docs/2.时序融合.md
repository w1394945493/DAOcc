1. BEVDet4D的实现梳理：

| 问题 | 答案 |
|---|---|
| 当前帧的历史帧如何确定？ | pkl 保存各帧信息；Dataset 按时间排序后，根据当前索引和配置的偏移量选择历史帧。 |
| 历史对应关系提前保存在 pkl 中吗？ | 这里不是预先保存固定的历史帧组合，而是在 Dataset 取样时，从 `data_infos` 中选择。 |
| 历史帧是关键帧还是非关键帧？ | 标准数据流程中是 **nuScenes 关键帧**，不是 LiDAR sweeps 或关键帧之间的非关键帧。 |
| 只能使用上一帧吗？ | 支持多帧。普通 `4d` 配置使用前 1 帧，`4dlongterm` 配置使用前 8 帧。 |
| 历史不足、跨场景时怎么办？ | 索引下限截到 0；候选帧不属于当前场景时，用当前帧代替。 |
| 训练时历史 BEV 如何得到？ | 加载历史图像，用当前网络权重**重新前向计算**，不读取上一 iteration 的缓存。历史分支使用 `torch.no_grad()`。 |
| 普通测试时历史 BEV 如何得到？ | 同样加载历史图像并重新计算。`model.eval()` 不会自动启用缓存。 |
| 顺序推理时能否使用缓存？ | 可以通过 `sequential=True` 和外部传入的 `feat_prev` 复用历史 BEV，本次只计算当前帧 BEV。 |
| 模型会自动维护跨帧缓存吗？ | 该顺序推理接口不自动维护缓存队列，需要调用者保存、更新历史特征及位姿，并处理场景切换。 |
| 多帧 BEV 如何融合？ | 对齐到当前帧坐标系，沿通道维拼接，再输入 BEV 编码器。 |

参考StreamOcc，在DAOcc基础上，实现流式占据预测：
1. 把 DAOcc 从独立帧处理接入连续序列处理，打通数据组织、历史缓存、空间对齐，以及训练中流式评估。
| 部分 | 已完成的内容 |
|---|---|
| **序列数据集** | 按场景和时间组织帧，参照 StreamOcc 支持 `sequences_split_num` 切分子序列；提供序列标识、首帧标记、位姿和增强元数据 |
| **训练采样** | 使用序列 batch sampler，解除流式分支的帧级 CBGS 和随机重采样；每个 batch 槽位连续读取自己的子序列，支持多 batch、多卡分配 |
| **增强一致性** | 默认同一子序列内保持图像与 LiDAR 几何增强一致，也允许配置为各帧独立增强；GridMask 和点打乱保留原有行为 |
| **模型接入** | 新增 `StreamingBEVFusion`，复用原 DAOcc 和 spconv2 计算路径，在最终 BEV 特征进入预测头前接入历史处理接口 |
| **历史缓存管理** | 按槽位缓存上一帧 BEV 及其元数据；读取历史后更新当前缓存，缓存脱离计算图；首帧无历史、切换子序列时分别处理，不清空其他槽位 |
| **历史 BEV 对齐** | 根据前后帧位姿及增强矩阵，将历史 BEV warp 到当前帧增强后的 LiDAR 空间，并生成有效区域掩码 |
| **训练中流式评估** | 验证集按连续序列读取，多卡按完整序列分配；评估使用当前训练权重，采用独立缓存，结束后恢复训练缓存和模型状态 |
| **训练状态维护** | 接入迭代式训练、优化器、混合精度、checkpoint 和 EMA 维护与保存；主模型与 EMA 分别恢复，续训时历史缓存重新建立 |
| **可视化检查工具** | 支持选择 train、val 或两者及多卡执行；按卡、槽位、场景保存原始历史 BEV、对齐后的历史 BEV、当前 BEV，并记录帧对应、增强和缓存检查信息 |
| **原流程隔离** | 通过独立流式配置和条件分支启用，复用原训练入口，原非流式配置保留原路径 |

当前每一步的数据流可以概括为：
各槽位读取连续帧
    ↓
提取当前帧 BEV
    ↓
读取对应槽位的历史 BEV 与元数据
    ↓
处理首帧 / 子序列切换
    ↓
将历史 BEV 对齐到当前帧，生成有效掩码
    ↓
历史处理接口 ← 下一阶段在这里加入时序融合
    ↓
原 DAOcc 预测头
同时，将本帧 BEV 和元数据写入缓存，供下一帧使用。

3. 过滤缺少3D GT的帧：
说明：空检测 GT 是合法样本，不等于错误标注。
需要考虑：
| 方面 | 应如何处理 |
|---|---|
| **空 GT 的定义** | 判断有效性筛选、目标类别筛选，以及**实际增强和范围过滤后**是否还存在检测 GT；不是看原始框数量，也不是看 OCC 是否为空 |
| **跳帧的位置** | 由 sampler 推进索引，不能让 Dataset worker 私自换帧，否则会导致重复取帧、元数据与缓存不对应 |
| **每个 batch 槽位独立** | 只推进空帧所在槽位，其他槽位继续自己的序列；不缩小 batch |
| **增强参数一致** | 预检查与实际 pipeline 使用同一组参数；子序列固定增强时，跳过空帧不能重新抽增强 |
| **子序列边界** | 开头空帧被跳过后，首个有效帧仍是首帧；整段为空则继续下一段，正确重置历史 |
| **历史缓存** | 缓存保留上一次实际参与训练的帧，用它的真实时间戳和位姿对齐；不能假定历史一定是紧邻原始帧 |
| **验证和评估** | 保留全部帧，不能因为没有检测 GT 而漏评 OCC 或检测假阳性 |
| **效率与异常处理** | 预检查只处理标注；避免全空数据导致无限循环，并核对实际 pipeline 的结果 |
| **训练计数** | `max_iters` 仍按有效 batch 计数；原先按 28130 帧折算的“epoch”不再代表过滤后数据的一遍 |

4. (11.13) 总结流式训练：
增强策略：改变输入或时序上下文
| 策略 | 参数 | 默认 |
|---|---|---|
| 原有图像、点云几何增强 | 原 pipeline 配置 | 沿用 DAOcc |
| 子序列内复用几何增强参数；也可逐帧独立采样 | `keep_consistent_seq_aug` | `True` |
| 随机额外跳过一帧，改变时间间隔 | `skip_prob` | `0.0`，关闭 |
| 随机反转整段时间顺序 | `sequence_flip_prob` | `0.0`，关闭 |
不同相机分别生成图像增强参数；同一子序列再次被抽中，会重新采样增强。GridMask、点打乱等不受段内几何增强一致性约束。
机制策略：保证数据选择和历史对应正确
| 机制 | 作用／默认设置 |
|---|---|
| 场景分组、时间排序 | 建立连续序列 |
| 子序列切分 | `sequences_split_num=2`，每场景两段 |
| 段间随机、段内按选定方向读取 | 保留时序关系并随机切换子序列 |
| 多卡、多 batch 槽位独立推进 | 各槽位读取自己的序列 |
| 无限采样＋迭代数控制 | 由 `runner.max_iters` 决定训练长度 |
| 空 GT 预计算与顺序跳过 | `skip_empty_gt=True`，避免随机换帧 |
| 子序列级 CBGS | `sequence_cbgs=False`，可选类别均衡采样 |
| 显式序列边界与方向标记 | `sequence_start`、`sequence_instance`、`sequence_direction` |
| 槽位历史隔离与重置 | 新段开始时旧历史失效，重复抽到同段也重新开始 |
| 验证使用独立读取规则 | 正序完整场景，不启用训练跳帧、反序和 CBGS |
