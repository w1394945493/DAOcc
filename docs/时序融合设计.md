1. BEVDet4D的实现梳理：

| 问题 | 答案 |
|---|---|
| 当前帧的历史帧如何确定？ | pkl 保存各帧信息；Dataset 按时间排序后，根据当前索引和配置的偏移量选择历史帧。 |
| 历史对应关系提前保存在 pkl 中吗？ | 这里不是预先保存固定的历史帧组合，而是在 Dataset 取样时，从 `data_infos` 中选择。 |
| 历史帧是关键帧还是非关键帧？ | 标准数据流程中是 **nuScenes 关键帧**，不是 LiDAR sweeps 或关键帧之间的非关键帧。 |
| 只能使用上一帧吗？ | 支持多帧。普通 `4d` 配置使用前 1 帧，`4dlongterm` 配置使用前 8 帧。 |
| 历史不足、跨场景时怎么办？ | 索引下限截到 0；候选帧不属于当前场景时，用当前帧代替。 |
| 训练时历史 BEV 如何得到？ | 加载历史图像，用当前网络权重**重新前向计算**，不读取上一 iteration 的缓存。历史分支使用 `torch.no_grad()`。 |
| 普通测试时历史 BEV 如何得到？ | 同样加载历史图像并重新计算。`model.eval()` 不会自动启用缓存。 |
| 顺序推理时能否使用缓存？ | 可以通过 `sequential=True` 和外部传入的 `feat_prev` 复用历史 BEV，本次只计算当前帧 BEV。 |
| 模型会自动维护跨帧缓存吗？ | 该顺序推理接口不自动维护缓存队列，需要调用者保存、更新历史特征及位姿，并处理场景切换。 |
| 多帧 BEV 如何融合？ | 对齐到当前帧坐标系，沿通道维拼接，再输入 BEV 编码器。 |
