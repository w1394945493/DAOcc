| 多帧 BEV 如何融合？ | 对齐到当前帧坐标系，沿通道维拼接，再输入 BEV 编码器。 |

|---|---|
| **空 GT 的定义** | 判断有效性筛选、目标类别筛选，以及**实际增强和范围过滤后**是否还存在检测 GT；不是看原始框数量，也不是看 OCC 是否为空 |

| **子序列边界** | 开头空帧被跳过后，首个有效帧仍是首帧；整段为空则继续下一段，正确重置历史 |

5. (11.15) 目前历史细化模块新增参数

| 模块 | 参数量 |
|---|---:|
| 历史特征缓存 | 0 |
| BEV warp 对齐 | **0** |
| RefineNet 历史细化 | **313,698** |
| 拼接融合模块 | **525,312** |
| **合计** | **839,010** |


839,010 个参数 ≈ 0.839 M，约 0.84 M（约 83.9 万参数）。

RefineNet 的参数组成：

| 组成 | 结构 | 参数量 |
|---|---|---:|
| 瓶颈卷积及 BN | `512 → 128 → 128 → 512`，卷积核 `1×1、3×3、1×1` | 280,832 |
| 通道注意力 | `512 → 32 → 512` | 32,768 |
| 空间注意力 | `2 → 1`，`7×7` 卷积 | 98 |

计算规则是：
- 普通卷积：输出通道 × 输入通道 × 核高 × 核宽，若有 bias，再加 输出通道。
- BatchNorm：每个通道有两个可学习参数 γ、β，因此为 2 × 通道数。
- ReLU、池化、sigmoid 没有可学习参数。

① 瓶颈卷积及 BN：280,832

这里三个卷积都使用 bias：

| 层 | 计算 | 参数量 |
|---|---|---:|
| `1×1 Conv：512→128` | `128×512×1×1 + 128` | 65,664 |
| `BN：128` | `128×2` | 256 |
| `3×3 Conv：128→128` | `128×128×3×3 + 128` | 147,584 |
| `BN：128` | `128×2` | 256 |
| `1×1 Conv：128→512` | `512×128×1×1 + 512` | 66,048 |
| `BN：512` | `512×2` | 1,024 |
| **合计** | | **280,832** |

② 通道注意力：32,768

两个 1×1 卷积均设置了 bias=False：

512 → 32：32 × 512 = 16,384
32 → 512：512 × 32 = 16,384

合计：32,768

平均池化和最大池化结果复用同一套卷积权重，因此不翻倍。

③ 空间注意力：98

沿通道分别求均值和最大值，得到两张图，拼接成 2 通道。随后使用不带 bias 的 7×7 卷积：

2 → 1：1 × 2 × 7 × 7 = 98


6. （11.17）神经微分方程：从历史特征融合到状态演化的思考

6.1 出发点：运动补偿后，历史信息仍可能过时

现有流式流程为：

历史缓存 → 自车运动补偿 → RefineNet → 与当前 BEV 拼接融合
                                           ↓
                                   当前预测及缓存更新

自车运动补偿解决的是坐标变化，无法消除动态目标运动、遮挡变化等影响。因此进一步思考：能否结合真实时间间隔，让历史状态向当前时刻演化，再用于当前预测？

需要区分：

| 概念 | 含义 |
|---|---|
| 物理运动演化 | 位置、速度等物理量随时间变化 |
| 预测状态演化 | 历史表征随时间推进，支持目标时刻的预测 |
| 观测驱动的状态演化 | 利用新观测提供的变化信息，持续更新历史表征 |

当前讨论主要针对后两者，不要求每个特征通道具有明确的物理含义。


6.2 初步设想：两种 ODE 接入方式

| 对比 | 串行演化 | 并行辅助预测 |
|---|---|---|
| 结构 | ODE → RefineNet → 融合 | 原融合路径保留，ODE 单独预测当前状态 |
| ODE 的作用 | 直接处理参与预测的历史特征 | 学习历史到当前状态的关系 |
| 学习方式 | 原有检测、占据损失 | 额外的一致性损失 |
| 主要问题 | 是否真正利用时间，还是退化为普通特征修正 | 目标包含当前新观测，并非全部可由历史预测 |

方案一：串行

已对齐历史 → ODE(Δt) → RefineNet ─┐
                                ├→ 拼接融合 → 当前状态 → 预测 / 缓存
当前帧 BEV ─────────────────────┘
 检测 / 占据预测           

方案二：并行

已对齐历史 → RefineNet ─┐
                       ├→ 拼接融合 → 当前状态 → 预测 / 缓存
当前帧 BEV ────────────┘                 │
                                        ↓
已对齐历史 → ODE(Δt) → 预测状态 ──→ 一致性约束

并行方案还需明确梯度路径：如果历史输入和目标状态均停止梯度，一致性损失只训练 ODE，不会直接改善主模型。

6.3 进一步追问：加入 ODE，是否就意味着学到了演化？

不一定。若时间间隔基本固定，ODE 更新可能接近普通残差变换；即使使用真实 Δt，也不能自动证明它学到了合理的场景变化。
因此，关注点从“在哪里插入 ODE”，转向：
- 演化的状态是什么？
- 状态变化由时间、历史信息，还是新观测驱动？
- 演化结果通过什么目标获得时间含义？
串行接入与演化监督也并不互斥，可以同时设计。

6.4 文献启发：自主推进与观测驱动是两条路线
- StreamingFlow：通过连续时间动力学推进 BEV 隐状态，在有观测时更新，并利用对应时刻的预测监督建立时间联系。论文
- EvoOcc：先补偿自车运动，再利用前后观测的变化驱动历史状态更新，强调当前观测对演化过程的控制。论文
由此，问题进一步变为：
是让历史自主预测当前，还是利用当前观测的变化，指导历史应该如何更新？

6.5 核心动机：较大的特征差异，不一定意味着场景真的变化

当前与对齐历史之间的差异，可能来自不同原因：

| 差异来源 | 希望模型采取的行为 |
|---|---|
| 动态目标发生运动 | 更新历史，避免保留旧位置 |
| 当前观测稀疏、噪声较大 | 保留仍可信的历史信息 |
| 遮挡或可见性发生变化 | 结合当前证据与历史可信度决定更新方式 |
| 新区域进入视野 | 主要依靠当前观测补充信息 |

因此，研究动机可以进一步明确为：
面向多模态流式占据预测，区分场景变化与观测不确定性，控制历史特征的保留、演化和替换。

这里不能写成“通过演化就能让模型具备区分能力”。这种区分是待解决的问题，需要明确的观测依据与更新机制，ODE 本身并不保证实现。

6.6 对现有实现的具体启发
若利用观测变化驱动更新，应比较同一处理阶段的特征：

\[
\Delta F_t=F_t-\operatorname{Warp}(F_{t-1})
\]

其中 \(F_t\) 和 \(F_{t-1}\) 都是尚未经过时序融合的当前帧观测特征。
不能直接用“当前未融合 BEV”减去“历史融合缓存”，因为二者处理阶段不同，差异同时混入了融合模块带来的变化。
整体思路因此逐步收敛为：
历史融合状态 ──→ 自车运动补偿 ──────────────┐
                                           ↓
前后同阶段观测 ──→ 对齐后的观测变化 ──→ 历史状态更新
                                           ↑
                              观测可靠性 / 历史可信度
                                           ↓
                                  当前预测及缓存更新
当前阶段的重点是明确状态更新的依据与机制，再判断 ODE 或受控动力学是否是合适的实现形式，而不是将“引入 ODE”本身作为主要创新点。
