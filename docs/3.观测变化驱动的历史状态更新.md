# 观测变化驱动的历史状态更新

记录日期：2026-11-17。

## 1. EvoOcc 带来的启发

我们不必让历史独自“猜到当前”，而可以利用当前观测的变化，指导历史信息更新。这更贴合 DAOcc 每帧都能获得相机、LiDAR 观测的流式处理过程。

原 RefineNet 在细化阶段只根据对齐历史自身产生修正，当前观测随后才在 Cat 融合阶段加入。这里希望让**历史修正本身就参考当前证据**，包括历史记忆、当前观测、对齐后的观测变化与实际时间间隔。

EvoOcc 利用快慢模型间的补充信息构建状态，再由快速模型的观测变化驱动状态更新。我们借鉴其受控更新结构，而不照搬快慢模型设定：DAOcc 当前没有独立的高质量慢模型，历史记忆也不天然比当前观测更准确。

本阶段定位为：**观测变化驱动的历史状态更新**。不预先将其认定为可靠的物理运动建模。

参考：[Fast-Slow Evolutionary Occupancy Prediction via Controlled Dynamics（EvoOcc）](https://arxiv.org/html/2611.02499v1)，重点为第 3 节及附录 B。

## 2. 区分当前观测与历史记忆

以下以 decoder 前融合为例：

| 符号 | 含义 | 缓存用途 |
|---|---|---|
| $F_t$ | 当前帧多模态融合生成、尚未经过时序融合的 BEV | 与下一帧同阶段特征比较，提供观测变化依据 |
| $H_t$ | 历史与当前观测经过时序融合得到的 BEV | 保存跨帧积累的信息，作为下一帧记忆 |
| $W$ | 历史到当前坐标系的 warp，包含自车运动及几何增强变换 | 将两份历史对齐到当前网格 |

可视化中的“更新后的当前 BEV”不是单纯的当前观测，而是吸收当前观测后的记忆状态。

两份历史共用元数据、有效性判断与生命周期，均以 `detach` 形式缓存；增加一份缓存不意味着重新提取历史帧特征。

### 2.1 同阶段比较观测变化

定义：

$$
\widetilde H=W(H_{t-1}),\qquad
\widetilde F=W(F_{t-1}),\qquad
\Delta F_t=F_t-\widetilde F.
$$

不采用 $F_t-W(H_{t-1})$ 作为观测变化，因为融合状态与原始观测属于不同处理阶段，其差异同时包含时序融合引起的表征变化。

即使比较同阶段特征，$\Delta F_t$ 仍只是变化证据，可能包含运动、遮挡、点云采样、逐帧增强、插值以及训练期间编码器参数更新的影响。

## 3. 从状态更新到受控动力学

概念性更新框架为：

$$
H_t^-=\widetilde H+
\Phi_\theta(\widetilde H,F_t,\Delta F_t,\Delta t).
$$

其中 $H_t^-$ 表示经过修正的历史，尚未完成与当前观测的最终融合。

在已经补偿自车运动的坐标系内，可用受控动力学描述：

$$
dH=A_\theta(H,F)\,dt+B_\theta(H,F)\,dF.
$$

| 项 | 含义 |
|---|---|
| $A_\theta(H,F)\,dt$ | 时间推进带来的状态变化 |
| $B_\theta(H,F)\,dF$ | 观测变化驱动的状态变化 |

采用当前端点观测形成离散更新：

$$
\delta H=A_\theta(\widetilde H,F_t)\Delta t
+B_\theta(\widetilde H,F_t)\Delta F_t,
\qquad H_t^-=\widetilde H+\delta H.
$$

这是当前帧观测到达后的受控更新，不是没有当前观测时的自主预测。$\Delta F_t$ 已是时间区间内的观测增量，**不再额外乘一次 $\Delta t$**。

当前实现采用这一思路的单步、因子化离散更新，不包含通用 ODE 求解器；不能将任意残差网络或本模块的性能收益直接等同于准确学习了连续物理动力学。

## 4. 借鉴 EvoOcc 的因子化实现

EvoOcc 将状态增量分解为上下文调制与控制增量投影的乘积，避免为每个位置生成完整的通道变换矩阵。借鉴这一结构，在 DAOcc 中定义：

$$
V=P_\theta\left([\Delta F_t,\Delta t/\tau_0]\right),
$$

$$
Q=\operatorname{Bottleneck}_\theta([\widetilde H,F_t]),
$$

$$
M=\alpha\,a_c(Q)\odot a_s(Q),\qquad
\delta H=M\odot V,
$$

$$
\boxed{H_t^-=\widetilde H+\delta H}.
$$

以上公式描述有效历史区域；首帧及越界处理见第 7 节。

| 组成 | 当前设计 |
|---|---|
| $P_\theta$ | 无偏置 `1×1 Conv`，将 $C+1$ 通道投影为 $C$ 通道 |
| $\tau_0$ | 时间尺度，默认 1 秒 |
| $Q$ | 历史记忆与当前观测共同生成的局部上下文 |
| $a_c$ | 通道调制，形状为 $B,C,1,1$ |
| $a_s$ | 空间调制，形状为 $B,1,X,Y$ |
| $\alpha$ | 固定更新缩放系数，默认 0.1，作用于整个训练和推理过程，不只在初始化时生效 |
| $V,\delta H$ | 候选更新与实际更新，形状均为 $B,C,X,Y$ |

无偏置投影保证控制增量全零时，更新增量也为零。但当 $\Delta F_t=0$、$\Delta t\ne0$ 时，时间项仍可产生更新。

### 4.1 如何对应到 A 和 B

这是一种**受限的参数化选择**，不是从一般 $A_\theta、B_\theta$ 唯一推导出的结构。

将线性投影展开：

$$
V=W_F\Delta F_t+w_t\Delta t/\tau_0.
$$

代入更新式：

$$
\delta H
=\operatorname{Diag}(M)W_F\Delta F_t
+(M\odot w_t/\tau_0)\Delta t.
$$

于是：

$$
\boxed{
A_\theta=M\odot w_t/\tau_0,\qquad
B_\theta=\operatorname{Diag}(M)W_F
}.
$$

这里的 $\operatorname{Diag}(M)$ 表示每个空间位置的逐通道调制，代码不显式构造对角矩阵。

通俗地说，$V$ 提供候选更新，$Q$ 提供上下文，$M$ 决定响应强度，$\delta H$ 才是最终施加到记忆上的变化。时间项与观测变化项共享 $M$，比两个完全独立的更新网络更简洁，但表达能力也受到限制。

## 5. 如何借鉴原 RefineNet

原 RefineNet 的精确顺序可写为：

$$
R=\operatorname{Bottleneck}(\widetilde H),\qquad
R_c=a_c(R)\odot R,
$$

$$
H_{\mathrm{refine}}=\operatorname{ReLU}
\left(\widetilde H+a_s(R_c)\odot R_c\right).
$$

新模块保留其瓶颈与注意力设计思想，但改变职责：

| 结构 | 原 RefineNet | 新受控更新 |
|---|---|---|
| 瓶颈卷积 | 根据历史生成修正特征 | 联合历史与当前观测生成上下文 $Q$ |
| 通道注意力 | 调制历史修正特征 | 调制控制增量的通道响应 |
| 空间注意力 | 根据通道调制后的特征生成空间权重 | 根据 $Q$ 生成空间权重，与通道调制共同作用于 $V$ |
| 残差连接 | 历史加自身修正，再 ReLU | 历史加受控更新，不额外 ReLU |

当前代码中上下文分支使用 `1×1 → 3×3 → 1×1` 卷积，中间使用 GroupNorm 和 SiLU；通道调制使用平均/最大池化及共享映射，空间调制使用通道平均/最大值和 `7×7` 卷积。

**原来由历史自身生成修正量；现在由观测变化与时间生成候选更新量，由历史和当前上下文调制。**

新模块替代原 RefineNet，不再额外叠加完整 RefineNet；后续仍使用原 Cat 融合。增量允许正负值，残差更新后不使用 ReLU，以免将额外的截断投影混入更新定义。

## 6. 整体流程

```text
历史记忆 H(t−1) → 自车运动补偿 → 对齐历史 ──────────────┐
                                     │                │
当前观测 F(t) ────────────────────────┤                │
                                     ↓                │
                              上下文 Q / 调制 M        │
                                     │                │
历史观测 F(t−1) → 自车运动补偿 ─┐     │                │
                               ├→ ΔF │                │
当前观测 F(t) ─────────────────┘     │                │
                                │    │                │
实际 Δt ────────────────────────┤    │                │
                                ↓    │                │
                         控制投影 V ─×→ 更新增量 ───→ 残差相加
                                                      ↓
                                                 更新后的历史
                                                      │
当前观测 F(t) ────────────────────────────────────────┤
                                                      ↓
                                                 Cat 拼接融合
                                                      ↓
                                            当前记忆 H(t)
                                              │       │
                                              ↓       ↓
                                           decoder   缓存 H(t)
                                              ↓
                                        检测 / 占据预测

同时缓存本帧 F(t)，供下一帧计算同阶段观测变化。
```

## 7. 边界、梯度与解释范围

- **首帧/序列切换**：没有有效历史，历史更新输出回退当前特征，再进入 Cat 融合。代码仍计算被掩码的分支，使参数参与计算图，避免首帧引入额外的 DDP 未使用参数问题；其输出不影响回退结果。
- **warp 越界**：将对应观测增量和时间控制量置零，更新结果回退当前特征，不能把“当前观测减去零填充”解释成场景变化。空间上下文仍会利用相邻位置，掩码不是运动或置信度标签。
- **跳帧/反序**：使用实际时间戳差，允许负值；支持带符号时间不意味着学到了可逆动力学。
- **梯度**：历史缓存与其 warp 停止梯度，当前观测、控制投影及调制网络正常参与反向传播。
- **数值计算**：当前实现中差分、控制网络及残差更新使用 FP32，新路径显式统一 Cat 输入为 FP32；旧路径保持原行为。小幅更新缩放不保证训练不会出现 NaN。
- **监督**：沿用原检测、占据损失，未增加拟合旧融合状态的一致性损失。
- **可信度解释**：注意力只是学习得到的调制系数，不直接等于置信度、动态目标概率或可靠性判断。

| [bev_history_fusion.py](../mmdet3d/models/fusers/bev_history_fusion.py) | 在新路径与原 RefineNet 路径之间选择，复用 Cat 融合 |

| [streaming_bevfusion.py](../mmdet3d/models/fusion_models/streaming_bevfusion.py) | 双缓存读写、复用 warp 网格、时间差与边界处理 |

配置位于 [流式配置](../configs/nuscenes/occ3d/daocc_occ3d_nus_w_mask_inin_spconv2_voxel_stream_cache.yaml) 的 `streaming.history_fusion` 下：

```yaml
use_refine: true
use_controlled_update: false
update_scale: 0.1
time_scale: 1.0
```

默认关闭新路径。训练命令显式开启：

```bash
--streaming.history_fusion.use_controlled_update True
```

开启后替代 RefineNet，`use_refine` 仅控制旧路径。新模块与旧细化模块参数结构不同，不能严格互换权重。

与原 RefineNet 的实验是整体更新方案对照，同时涉及输入依据、网络结构、归一化、边界处理和局部精度变化，不能将收益单独归因于 ODE、时间间隔或观测差分。

## 9. RefineNet 上的观测引导（2026-11-20）

新增 `BEVGuidedRefineNet`（`bev_guided_refine.py`），保留原 RefineNet 的完整
BN/ReLU 瓶颈、串行通道/空间注意力与最终 ReLU。观测引导不替代历史修复内容，
而是给原注意力的 sigmoid 前 logits 添加偏置。

引导输入为 `[F_t, ΔF, Δt/τ₀, valid_mask]`；前三项在无效历史区域清零。
引导分支使用 `1×1 → GN → SiLU → 3×3 → GN → SiLU`，默认宽度 64。
通道偏置由有效区域平均池化产生；空间偏置逐位置产生。新增偏置头在外层
Xavier 初始化之后清零，因此相同原主干及 Cat 权重下，初始输出与原方案一致。
全无历史时仍执行引导计算图，但引导参数梯度为零。空间卷积允许邻域影响跨越 mask 边界。

首帧、无效历史槽位与 warp 零填充均沿用原 RefineNet 的处理方式；mask 只控制
新增引导，不像旧 controlled 路径那样将越界修复输出直接替换为当前观测。
两种新模式都缓存融合前观测，但历史处理语义独立。

训练时在原命令中指定（并使用独立 run-dir）：

```bash
--streaming.history_fusion.mode guided_refine \
--streaming.history_fusion.guide_channels 64 \
--streaming.history_fusion.time_scale 1.0
```

可视化使用同一配置覆盖：

```bash
--cfg-options \
streaming.fuse_before_decoder=True \
streaming.history_fusion.mode=guided_refine \
streaming.history_fusion.guide_channels=64
```

`mode: null` 保持旧布尔开关的解释规则；显式 mode 优先，支持 `identity`、
`refine`、`controlled_update`、`guided_refine`。旧 `update_scale` 仅用于
controlled 模式，不缩放 guided 模式的修复残差。
原 RefineNet 移至 `bev_refine.py`，原导入位置仍可访问该类，旧 checkpoint
参数路径不变。guided 模式的原主干仍位于 `history_fusion.refine_net.*`。
从 baseline 初始化需显式检查缺失键仅属于 `guide`、`channel_bias`、`spatial_bias`，
且不存在 unexpected keys；本改动不放宽正式可视化的严格 checkpoint 加载。
旧 controlled checkpoint 不能作为 guided 模式完整权重加载。

512/128 通道配置下，原 RefineNet 参数量 313,698，旧 controlled 为 640,866，
guided（guide_channels=64）为 449,955，均不包含公共 Cat 层。
这是一种观测引导修复结构，不再强制解释为 `AΔt+BΔF` 的动力学参数化。
